クラウド型ドローン測量サービス「KUMIKI」の開発・運用に従事（チーム約10名、登録ユーザー数1万人弱、画像処理リクエストは1日平均約30件）。AWS処理基盤・バックエンドを中心にReactの画面開発まで担当し、外国籍メンバーとは英語で会議・共同作業を行っています。

#### GPU処理基盤の安定化

- GPUインスタンスを確保できない際にLambdaが再帰的に起動を試みる構成を見直しました。従来は繁忙期に月1回程度、滞留した処理の手動復旧が必要で、多重起動による不要な課金も発生していました。
- 技術選定・設計・構築を主担当として進め、AWS Batchによるキューイング基盤へ移行しました。ジョブの優先度と受付順を維持して待機させ、複数のインスタンスタイプから利用可能なGPUリソースを確保する構成としました。
- 導入後約3か月間、GPUインスタンスの枯渇に伴う手動復旧を0件にし、Lambdaの多重・再帰実行による不要な課金も削減しました。
- 社内で初めてTerraformを導入し、インフラ構成を再現・拡張しやすい形でコード管理しました（LambdaはAWS SAMで管理）。

**技術：** AWS Lambda（Node.js）、AWS Batch、Terraform、AWS SAM

#### 後続処理の失敗を防ぐ画像検証APIの構築

- 不適切な空撮画像による後続処理の失敗を防ぐため、画像のメタ情報をリアルタイムで検証するマイクロサービスを構築しました。
- ECS / Fargate上でFastAPIのAPIサーバーと検証処理サーバーを分離し、ElastiCache for Redisをジョブキュー・キャッシュとして利用しました。
- 要件整理、技術選定、AWS構成、API設計、実装、テストまで一貫して担当し、応答時間10秒以内の要件を満たしました。

**技術：** Python、FastAPI、Amazon ECS、AWS Fargate、Amazon ElastiCache for Redis

#### 処理停止の検知と本番障害への対応

- 一定時間進捗がなく完了しない処理を検知し、Slackへ通知する監視ツール群をAWS Lambdaで構築しました。監視条件の設計から実装・テストまで主担当として進め、利用者の申告を待たずに処理停止を発見できるようにしました。
- ファイル未生成や処理停止などの本番障害では、アプリケーションログ、DB上の処理状態、S3上の生成ファイルを照合して原因を特定しました。
- 再処理・ファイル補完による暫定復旧から、恒久対策の設計・実装・リリースまで一貫して担当しました。

**技術：** AWS Lambda、Amazon S3、Slack

#### 座標系候補の提示機能をAPIから画面まで開発

- 空撮画像の位置情報から座標系を判定し、ユーザーへ候補として提示する機能を開発しました。
- 地形ポリゴンから撮影地点を含む領域を検索する処理を、Lambda Function URLで呼び出すAPIとして実装し、外部のReverse Geocoding APIを使わずに判定できる構成としました。
- Lambda API、Laravelバックエンド、Reactでの候補表示まで、一連の機能を横断して担当しました。

**技術：** Python、AWS Lambda、Lambda Function URL、PHP、Laravel、React、GIS

#### 既存機能・保守性の改善

- 地形画像生成処理の責務・依存関係が不明確だったため、チームで処理構成を見直しました。自身は主要処理の分割・再配置、不要処理の削除、段階的な移行を担当しました。
- 単体テストと処理フロー全体の結合テストを整備し、変更・保守しやすい構成へ改善しました。
- 地図上に表示するPDFの管理APIをLaravelで開発し、MySQLのスキーマ変更・マイグレーション・テストを担当しました。

**技術：** Python、Amazon S3、PHP、Laravel、MySQL
