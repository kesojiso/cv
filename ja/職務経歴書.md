## 職務要約

フルスタックエンジニアとして、Webアプリケーション、クラウド基盤、データ処理システムの設計・開発・運用に従事してまいりました。要件整理や技術選定から、インフラ・バックエンドAPI・フロントエンド開発、テスト、運用保守まで一貫して担当できることを強みとしております。

現在はクラウド型ドローン測量サービスの開発に携わり、AWSをはじめとするクラウド基盤とバックエンドを中心に、画像処理APIやGPUを利用した非同期処理基盤の設計・実装から、リリース、障害対応などの運用まで担当しております。

前職では、大手ECサイトの推薦システム、AIを用いたWebアプリケーション、モバイルアプリの開発に加え、数千万～数十億レコード規模のマーケティングデータの処理・分析や施策の効果検証に従事しておりました。

こうした開発経験に加え、海外拠点や外国籍メンバーとの協働において日常的に英語を使用してまいりました。また、日々の開発業務にAIを取り入れるなど、業務を円滑かつ効率的に進めるための手段を積極的に活用しております。

クラウド型ドローン測量サービス「KUMIKI」の開発・運用に従事（チーム約10名）。AWS上の処理基盤、バックエンドAPI、Reactによるフロントエンド、本番運用まで横断して担当しております。

#### AWSを用いた非同期処理基盤の設計・構築

- 登録ユーザー数1万人弱、1日平均約30件の画像処理リクエストを扱うクラウド型ドローン測量サービスにおいて、GPU画像処理基盤の設計・構築を担当しました。
- 従来は、GPUインスタンスを確保できない場合にLambdaが再帰的に起動を試みる構成で、繁忙期には月1回程度、滞留した処理の手動復旧が必要でした。また、Lambdaの多重起動による不要な実行課金も発生していました。
- アーキテクチャと技術の選定から設計・構築までを主担当として進め、AWS Batchを用いて、GPUインスタンスが確保できるまでジョブを安全に待機させるキューイング基盤を構築しました。ジョブの優先度と受付順を維持しながら、複数のインスタンスタイプから利用可能なGPUリソースを確保できる構成としました。
- 導入後約3か月間、GPUインスタンスの枯渇に伴う手動復旧を0件にし、Lambdaの多重・再帰実行による不要な課金も削減しました。
- あわせて、将来のマルチクラウド展開を見据えて社内で初めてTerraformを導入し、インフラ構成を再現・拡張しやすい形でコード管理しました（LambdaはAWS SAMで管理）。

**技術：** AWS Lambda（Node.js）、AWS Batch、Terraform、AWS SAM

#### AWSを用いた画像検証マイクロサービスの設計・構築

- 不適切な空撮画像による後続処理の失敗を防ぐため、画像のメタ情報をリアルタイムで検証するマイクロサービスを構築しました。
- Amazon ECS on AWS Fargate上に、FastAPIによるAPIサーバーと検証処理サーバーをそれぞれ独立したFargateタスクとして構築しました。
- Amazon ElastiCache for Redisをジョブキューとキャッシュに利用し、APIサーバーと検証処理サーバーを分離した構成としました。
- 要件整理、技術選定、AWS構成、API設計、実装、テストまで一貫して担当し、応答時間10秒以内の要件を満たしました。

**技術：** Python、FastAPI、Amazon ECS、AWS Fargate、Amazon ElastiCache for Redis

#### サーバーレスAPIとWeb画面を横断した座標系判定機能の開発

- 空撮画像の位置情報から撮影地点の座標系をリアルタイムに判定し、ユーザーへ候補として提示する機能を開発しました。
- あらかじめ作成した地形ポリゴンから撮影地点を含む領域を検索する判定処理を実装し、AWS LambdaとLambda Function URLを用いた独立したサーバーレスAPIとして構築しました。
- ReactからLaravelバックエンドを経由してLambda APIを呼び出し、判定結果を画面上へ候補として表示する一連の処理について、Lambda API、Laravel、Reactの全レイヤーを担当しました。
- 外部のReverse Geocoding APIを利用せずに判定できる構成とし、API利用コストの削減と判定精度の向上につなげました。

**技術：** Python、AWS Lambda、Lambda Function URL、PHP、Laravel、React、GIS

#### LaravelによるバックエンドAPI開発

#### 本番運用・監視の改善

- **サイレント障害の検知：** 一定時間進捗がなく完了状態へ遷移しない処理を検知し、Slackへ通知する監視ツール群をAWS Lambdaで構築しました。監視条件、判定処理、通知、テストまで主担当として設計・実装し、利用者からの申告を待たずに処理停止を発見できるようにしました。
- **本番障害への対応：** ファイルが生成されない、処理が途中で停止するといった障害に対し、アプリケーションログ、データベース上の処理状態、Amazon S3上の生成ファイルを総合的に確認して原因を特定しました。対象データの再処理や生成ファイルの補完による暫定復旧から、恒久対策の設計・実装・リリースまで一貫して担当しました。

**技術：** AWS Lambda、Amazon S3、Slack
